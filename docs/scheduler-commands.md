# Документация по командам планировщика

Этот документ описывает команды планировщика Laravel, используемые в MMORPG игре.

## Настройка планировщика

Для работы планировщика Laravel необходимо добавить следующую строку в crontab:

```bash
* * * * * cd /path-to-project && php artisan schedule:run >> /dev/null 2>&1
```

Замените `/path-to-project` на абсолютный путь к проекту.

## Команды планировщика

### 1. Регенерация здоровья и маны персонажей

**Команда:** `characters:regenerate-health`

**Описание:** Восстанавливает здоровье и ману активным персонажам каждые 15 секунд.

**Частота выполнения:** Каждую минуту (через Laravel Scheduler)

**Что делает:**
- Находит всех активных персонажей с неполным здоровьем или маной
- Рассчитывает скорость регенерации для каждого персонажа:
  - **Здоровье:** Базовая скорость 1 HP за 15 секунд, увеличивается навыком `health_regeneration` (максимум 8 HP за 15 секунд)
  - **Мана:** Базовая скорость 1 MP за 15 секунд, зависит от интеллекта и навыка `mana_regeneration` (максимум 12 MP за 15 секунд при интеллекте 10 и навыке 10)
- Восстанавливает соответствующие ресурсы
- Выводит статистику восстановления

**Формулы расчета:**

**Регенерация здоровья:**
```
Регенерация HP = 1 + round(skill_level * 0.7)
```
- Базовая скорость: 1 HP за 15 секунд
- Максимум: 8 HP за 15 секунд (при навыке уровня 10)

**Регенерация маны:**
```
Регенерация MP = 1 + (intelligence - 1) * 0.5 + skill_level * 0.65
```
- Базовая скорость: 1 MP за 15 секунд (при интеллекте 1 и навыке 0)
- Максимум: 12 MP за 15 секунд (при интеллекте 10 и навыке 10)

**Примеры:**
- Интеллект 1, навык 0: 1 MP за 15 сек
- Интеллект 5, навык 5: 6 MP за 15 сек
- Интеллект 10, навык 10: 12 MP за 15 сек

**Настройка для запуска каждые 15 секунд:**

Если требуется запускать команду каждые 15 секунд вместо каждой минуты, добавьте в crontab:

```bash
*/15 * * * * cd /path-to-project && php artisan characters:regenerate-health >> /dev/null 2>&1
```

**Ручной запуск:**
```bash
php artisan characters:regenerate-health
```

---

### 2. Очистка истекших предметов

**Команда:** `items:clean-expired`

**Описание:** Удаляет предметы на земле с истекшим временем жизни.

**Частота выполнения:** Не настроена в планировщике (можно добавить)

**Что делает:**
- Находит все предметы на земле (`location_type = 'ground'`)
- Проверяет поле `expires_at` (время истечения)
- Удаляет предметы, у которых время истечения прошло
- Не удаляет квестовые предметы (где `owner_id` не null)

**Рекомендуемая частота:** Каждые 5-10 минут

**Добавление в планировщик:**

Добавьте в `routes/console.php`:

```php
Schedule::command('items:clean-expired')->everyFiveMinutes();
```

**Ручной запуск:**
```bash
php artisan items:clean-expired
```

---

### 3. Восстановление зарядов рун

**Команда:** `items:recharge-runes`

**Описание:** Восстанавливает заряды рун, у которых прошло время перезарядки.

**Частота выполнения:** Не настроена в планировщике (можно добавить)

**Что делает:**
- Находит все экземпляры рун в игре
- Проверяет время последней перезарядки (`last_recharge`)
- Сравнивает с временем перезарядки из `rune_data['recharge_time']` (в минутах)
- Восстанавливает заряды до максимума, если прошло достаточно времени

**Рекомендуемая частота:** Каждую минуту

**Добавление в планировщик:**

Добавьте в `routes/console.php`:

```php
Schedule::command('items:recharge-runes')->everyMinute();
```

**Ручной запуск:**
```bash
php artisan items:recharge-runes
```

## Добавление новых команд в планировщик

Все команды планировщика настраиваются в файле `routes/console.php`.

### Примеры настройки частоты:

```php
// Каждую минуту
Schedule::command('command:name')->everyMinute();

// Каждые 5 минут
Schedule::command('command:name')->everyFiveMinutes();

// Каждые 10 минут
Schedule::command('command:name')->everyTenMinutes();

// Каждый час
Schedule::command('command:name')->hourly();

// Каждый день в определенное время
Schedule::command('command:name')->dailyAt('13:00');

// В определенные дни недели
Schedule::command('command:name')->weeklyOn(1, '8:00'); // Понедельник в 8:00

// Каждый месяц
Schedule::command('command:name')->monthly();
```

### Примеры с условиями:

```php
// Только в рабочее время (9:00 - 17:00)
Schedule::command('command:name')
    ->hourly()
    ->between('9:00', '17:00');

// Только в определенные дни недели
Schedule::command('command:name')
    ->daily()
    ->days([1, 3, 5]); // Понедельник, среда, пятница

// С ограничением на один сервер (для кластеров)
Schedule::command('command:name')
    ->hourly()
    ->onOneServer();
```

## Тестирование команд на локальной машине

Для тестирования команд планировщика на локальной машине есть несколько способов:

### 1. Ручной запуск отдельных команд

Самый простой способ протестировать команду - запустить её вручную:

```bash
# Регенерация здоровья и маны
php artisan characters:regenerate-health

# Очистка истекших предметов
php artisan items:clean-expired

# Восстановление зарядов рун
php artisan items:recharge-runes
```

Это позволит сразу увидеть результат выполнения команды и проверить её работу.

### 2. Запуск планировщика один раз

Для тестирования всех запланированных команд за один раз:

```bash
php artisan schedule:run
```

Эта команда выполнит все задачи, которые должны были выполниться в текущую минуту. Полезно для проверки конфигурации планировщика.

### 3. Постоянный запуск планировщика (рекомендуется для разработки)

Для постоянного выполнения команд в режиме разработки используйте:

```bash
php artisan schedule:work
```

Эта команда будет запускать планировщик каждую минуту автоматически, пока вы не остановите процесс (Ctrl+C). Это идеальный способ для локального тестирования, так как:
- Не требует настройки crontab
- Автоматически выполняет все запланированные команды
- Легко остановить и перезапустить

**Важно:** По умолчанию Laravel перенаправляет вывод команд в `/dev/null`, поэтому вы не увидите результат выполнения команды. Для просмотра вывода используйте один из способов ниже.

**Способ 1: Просмотр логов планировщика**

Вывод команд сохраняется в `storage/logs/scheduler.log`:

```bash
# В отдельном терминале следите за логами
tail -f storage/logs/scheduler.log
```

**Способ 2: Запуск команды напрямую для тестирования**

Для просмотра вывода в реальном времени запустите команду напрямую:

```bash
php artisan characters:regenerate-health
```

**Способ 3: Изменение конфигурации для видимого вывода (только для разработки)**

Если хотите видеть вывод прямо в терминале при `schedule:work`, временно измените `routes/console.php`:

```php
Schedule::command('characters:regenerate-health')
    ->everyMinute()
    ->sendOutputTo('/dev/stdout'); // Показывать вывод в терминале
```

**Пример использования:**

```bash
# Терминал 1: Запустить планировщик
php artisan schedule:work

# Терминал 2: Следить за логами
tail -f storage/logs/scheduler.log

# Терминал 3: Для ручного тестирования с видимым выводом
php artisan characters:regenerate-health
```

### 4. Просмотр списка запланированных задач

Перед тестированием полезно посмотреть, какие команды запланированы:

```bash
php artisan schedule:list
```

Эта команда покажет:
- Название команды
- Описание
- Расписание выполнения
- Следующее время выполнения
- Статус (включена/выключена)

### 5. Тестирование с измененной частотой

Для более частого тестирования можно временно изменить частоту выполнения в `routes/console.php`:

```php
// Для тестирования - каждые 10 секунд (вместо каждой минуты)
Schedule::command('characters:regenerate-health')->everyTenSeconds();

// Или каждые 30 секунд
Schedule::command('characters:regenerate-health')->cron('*/30 * * * * *');
```

**Важно:** После тестирования верните нормальную частоту выполнения!

### 6. Тестирование с отладочным выводом

Для более детального вывода добавьте флаг `-v` или `-vv`:

```bash
# Обычный вывод
php artisan characters:regenerate-health

# Подробный вывод
php artisan characters:regenerate-health -v

# Очень подробный вывод
php artisan characters:regenerate-health -vv
```

### 7. Проверка работы через логи

После выполнения команд проверьте логи:

```bash
# Просмотр последних записей в логе
tail -f storage/logs/laravel.log

# Или через Laravel Pail (если установлен)
php artisan pail
```

### Пример рабочего процесса для локального тестирования:

```bash
# 1. Откройте первый терминал - запустите планировщик
php artisan schedule:work

# 2. Откройте второй терминал - следите за логами
tail -f storage/logs/laravel.log

# 3. Откройте третий терминал - для ручных команд и проверки
php artisan schedule:list
php artisan characters:regenerate-health
```

### Рекомендации для разработки:

1. **Используйте `schedule:work`** для постоянного тестирования
2. **Запускайте команды вручную** для отладки конкретных проблем
3. **Проверяйте логи** после выполнения команд
4. **Используйте `schedule:list`** для проверки конфигурации
5. **Тестируйте на тестовых данных** перед использованием на продакшене

```php

// Регенерация здоровья и маны - каждую минуту
```

## Устранение неполадок

### Команды не выполняются

1. Проверьте, что crontab настроен правильно:
   ```bash
   crontab -l
   ```

2. Убедитесь, что путь к проекту указан абсолютный, а не относительный

3. Проверьте права доступа к файлам проекта

4. Убедитесь, что PHP доступен из командной строки:
   ```bash
   which php
   ```

### Команды выполняются слишком часто/редко

Измените частоту выполнения в файле `routes/console.php` или используйте crontab для более точного контроля.

### Проблемы с производительностью

Если команды выполняются слишком долго, рассмотрите:
- Оптимизацию запросов к базе данных
- Использование очередей для тяжелых операций
- Ограничение количества обрабатываемых записей за раз
